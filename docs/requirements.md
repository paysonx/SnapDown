# 需求分析文档 · 瞬下 SnapDown 万能视频下载

> 版本：v1.0（对应 MVP 首版）　更新时间：2026-09
> 用途：本文件是项目的需求基线。后续扩展功能（批量、字幕、AI 总结、会员付费等）前，AI/开发者应先阅读本文件，理解背景、已确认的决策与约束。

## 1. 项目背景与目标

很多用户有保存视频到本地的需求，但部分平台不支持下载、批量下载不方便、或有清晰度等限制。目标：做一个**万能视频下载网站**，更快、随时随地、从各平台下载视频，**手机上也能用**；未来可按需增加视频总结、字幕翻译、付费能力等。

## 2. 原始需求（用户描述）

- 万能视频下载：从各个平台快速下载视频，手机可用
- 可扩展：视频总结、字幕翻译、增加付费能力等
- 前端：尽量吸引人付费（突出实用价值）
- 后端：需要，但**先不需要数据库**，尽量轻量
- 下载核心：**不要自己承担风险**，站在巨人肩膀上，使用开源项目 [yt-dlp](https://github.com/yt-dlp/yt-dlp)（十几万 Star，支持 1000+ 平台），因此**技术栈以 Python 为主**

## 3. 关键决策记录（已经用户确认，勿随意推翻）

| 决策点 | 结论 | 备注 |
|---|---|---|
| 前端技术栈 | **Vue 3 + Tailwind 工程化前端（Vite 构建）** | 用户明确否决了原生 HTML/CSS/JS 方案 |
| 会员付费 | **首版不实现** | 前端暂不做价格卡片；未来扩展时再加分层+支付 |
| 首版功能范围 | **精简 MVP：解析 + 清晰度选择 + 下载 + 进度** | 批量/字幕/AI 总结/会员均为二期 |
| 部署目标 | **先本地运行跑通 + 预留部署配置** | 手机访问需后续部署服务器 |
| UI 参考 | 模仿 https://ai.codefather.cn/painting 的设计语言，但**要独特、不千篇一律** | 配色/文案/样式需利于未来付费转化 |
| 下载核心 | yt-dlp（PyPI 安装，Python 库直接封装，不做命令行调用） | 最小化代码改动 |

## 4. 参考网站 UI 研究结论（ai.codefather.cn/painting）

通过浏览器渲染 + HTML 源码 + AI 视觉问答完成拆解，结论如下（也是本项目设计语言的来源）：

| 设计要素 | 参考站风格 |
|---|---|
| 整体气质 | 白底、极简干净、无花哨光效（克制的高级感） |
| 主色 | 蓝色 `blue-600 (#2563eb)`；文字用 slate 灰阶 |
| 顶栏 | 白底 + 黑色粗体 Logo + 横向菜单 + 右侧蓝色圆角「登录/注册」按钮 |
| Hero | 居中 32px 粗体黑色大标题 + 16px 灰色副标题 + 居中大搜索框 |
| 卡片 | `rounded-xl` 圆角、细描边 `ring-slate-200`、悬停浮现蓝色光晕阴影 `shadow-blue-600/10`、图片缩放 105% + 渐变遮罩 |
| 标签 | `#标签` 小字灰色 → 悬停变蓝，中间灰点分隔 |
| 布局 | 瀑布流网格 + 简洁页脚 |

本项目的差异化：渐变闪电 Logo、渐变 CTA 按钮（blue→indigo）、蓝色氛围光背景、清晰度选择 chips、进度条动效，保持白底克制风格的同时增强品牌感与付费吸引力。

## 5. 功能需求

### 5.1 MVP（已实现）
1. 粘贴视频链接 → 解析视频信息（标题/封面/时长/作者/平台）
2. 清晰度选择（按分辨率降序 + "最佳画质"选项，显示格式/帧率/文件大小）
3. 下载（视频流 + 音频流自动合并输出 MP4）
4. 实时进度显示（百分比/速度/剩余时间/条纹进度条）
5. 下载完成后保存到本地 + 历史下载记录（内存，重启清空）
6. 移动端一键「粘贴」剪贴板链接 + 响应式布局

### 5.2 平台支持
- 能力范围 = yt-dlp 支持范围（1000+ 平台）
- **已实测**：B站（解析 + 360P/1080P/最佳画质下载 + 合并）✅
- **已实测**：抖音（解析 + 540P 真实下载，服务端自动生成游客身份与签名，**用户无需提供 Cookie**）✅
- **本机网络不可达**：YouTube、GitHub（实测超时；代码本身支持，部署到海外服务器或配代理即可）

### 5.3 二期候选（未实现，扩展时重新确认优先级）
- 批量/播放列表下载（当前接口明确拒绝播放列表，返回 400 提示）
- 字幕下载与翻译（parse 接口已返回字幕语言列表，前端未使用）
- AI 视频总结（需可配置 LLM API Key）
- 会员分层 + 付费（兑换码/支付网关接入）
- 持久化（数据库/文件）替代内存任务存储
- 服务器部署上线（手机随时访问）

## 6. 非功能需求

- **轻量**：无数据库、无消息队列，内存任务管理，单进程可跑
- **易用**：3 步完成（粘贴 → 选画质 → 保存），无需注册登录
- **移动优先**：手机浏览器完整可用，无横向滚动，触控目标 ≥ 44px
- **合规**：仅使用 yt-dlp 合法能力，**不碰 DRM 破解**；页面含版权提示（仅供个人学习使用）
- **性能**：解析秒级返回；下载进度 1 秒轮询；缩略图懒加载

## 10. 第三轮修复（2026，用户提出，已实现）

| # | 用户反馈 | 根因 | 实现 |
|---|---|---|---|
| 1 | 下载记录里的视频没有封面 | `/api/download` 只传了 `url + format_id`，`TaskManager.create()` 的 `title/thumbnail` 始终为空（历史记录只剩裸链接） | 后端：`DownloadRequest` 新增可选 `title/thumbnail` 并写入任务；`downloader._backfill_meta()` 在 progress_hook 与下载完成时用 yt-dlp 的 `info_dict` 兜底补齐；`_normalize_thumbnail()` 补全协议相对地址。前端：`startDownload()` 回传解析结果的标题与封面；`TaskList.vue` 增加封面加载失败回退占位图标 |
| 2 | 「© 2026 SnapDown」年份要动态变化 | 原本已是 `new Date().getFullYear()`，值为系统当前年份（本机为 2026），并非硬编码 | 提取为 `SiteFooter.vue` 的 `year` computed 并加注释；新增冒烟断言：伪造系统时间为 2027 年后页脚必须显示 `© 2027`（`页脚版权年份随系统时间动态变化`） |
| 3 | VIP 页「立即开通 VIP」点击后跳回了主页 | 写成了 `href="#plans"`；本站是 hash 路由，`#plans` 被解析成路由 `/plans`，未匹配即回退渲染主页 | 改为 `<button @click="scrollToPlans">` + `scrollIntoView`（尊重 `prefers-reduced-motion`）；App.vue 增加未知 hash 兜底：清理地址栏回主页，不再出现"路由落空仍渲染主页"；新增冒烟断言 `VIP 页「立即开通 VIP」滚动到本页套餐区（不跳主页）` 与 `未知 hash 自动回主页并清理地址栏` |
| 4 | 下载完成后点「再来一个」应回到刚进主页的初始界面 | 原 `handleReset` 只清了 `info/task/format`，**输入框仍留着旧链接**、页面也没回到顶部 | 抽取 `scroll.js`（`scrollToTop/scrollToElement/prefersReducedMotion/hasFinePointer`）统一滚动；`handleReset` 清空 `url`、错误、结果卡片，回到顶部，桌面端自动聚焦输入框（手机端不聚焦避免误弹键盘）；新增冒烟断言 `「再来一个」回到初始主页（清空链接 + 无结果卡片 + 回到顶部 + 恢复一屏）` |
| 5 | 同一视频先下 360P、再选其他分辨率，应重新下载对应分辨率，而不是复用第一次的文件 | 输出文件名模板 `%(title).120B [%(id)s].%(ext)s` 不含清晰度：同一视频所有清晰度同名，第二次下载被 yt-dlp 因"文件已存在"跳过 | 模板改为 `… [%(id)s] [%(format_id)s].%(ext)s`（实测 1080P=`100026+30280`、360P=`30016+30280`，天然唯一）；新增离线单测 `test_outtmpl_contains_format_id` 与集成测试 `test_download_two_resolutions_produce_distinct_files`（真实下载 360P + 480P，断言两个不同文件且都落盘） |
| 6 | 点「粘贴」应直接粘贴剪贴板内容，不要弹二次操作 | 先尝试 `execCommand('paste')` 反而在 Firefox 每次多弹一次"粘贴"确认框；Chrome 里它恒返回 false | 改为只用 `navigator.clipboard.readText()`（Chrome/Edge 首次一次授权后永久静默；Firefox 每次确认是浏览器安全机制、网页无法绕过），失败聚焦输入框；新增冒烟断言 `「粘贴」点击后直接填入剪贴板内容（无需二次操作）` |
| 7 | 下载记录里为每个视频加标签：分辨率、体量、下载时间（精确到分钟） | 任务原先只存 `format_id` 与 `created_at`，没有分辨率高度与文件体积 | 后端 `Task` 新增 `height`（yt-dlp `info["height"]` 回填）与 `filesize`（完成后取文件 `stat().st_size`）；前端 `TaskList` 卡片底部渲染三枚标签：蓝色「`height`P」、灰色「体积 MB/GB」、灰色「`YYYY-MM-DD HH:mm`」（取 `finished_at \|\| created_at`）；单测 `test_task_to_dict_includes_size_fields`、集成测试断言 `height == 所选分辨率` 且 `filesize > 0`、冒烟断言三标签渲染 |
| 8 | 主背景从全白改为渐变色白，更有吸引力 | 页面 `body` 为纯 `bg-white`，Hero/页脚/介绍页 Hero 也各自强制 `bg-white` | `body` 改为 `linear-gradient(180deg, #fff → #e6efff → #dee8ff → #f2ecff)`（`background-attachment: fixed`），并移除 Hero/页脚/介绍页 Hero 的 `bg-white` 让渐变透出；新增冒烟断言 `主页背景为渐变白（非纯白）` |
| 9 | 点「粘贴」仍会弹出一个「粘贴(P)」确认气泡 | **两个原因叠加**：① `document.execCommand('paste')` 会触发 Chromium 原生"粘贴(P)"确认气泡（需再点一次）；② 服务端未下发 `Cache-Control`，浏览器缓存了旧 `index.html` + 旧 bundle，重新构建后用户仍跑在旧 JS 上 | 前端彻底移除 `execCommand('paste')`，只用 `navigator.clipboard.readText()`，失败时聚焦输入框并提示手动 Ctrl+V；后端新增缓存中间件（入口 HTML `no-cache, must-revalidate`、`/assets/*` 指纹资源 `immutable` 长缓存）；新增 3 条冒烟断言：粘贴直接填入、被拒时提示并聚焦、产物不含 `execCommand`、缓存头正确 |
| 10 | 下载完成后的结果卡片布局要优化 | 下载完成后，清晰度选择区仍然可点但**界面上已无"下载"按钮，选中新画质不会重新下载**——是死控件；且 5 个清晰度排 3 列留一个空位、合并音轨提示此时已无意义 | 下载完成后（`isDone`）**收起整个清晰度选择区与合并提示**，改为清爽成功卡片（绿色对勾 + 「下载完成」+ 文件名 + `1080P`/体积/时长标签 + 「保存到本地」+「再来一个」），底色转 `bg-emerald-50/40`；清晰度区改用 `flex-wrap` + `basis` 让最后一行自动加宽铺满不留空位；新增冒烟断言 `下载完成后收起清晰度选择（不再有死控件）`、`下载完成卡片含标题与分辨率/体积标签、保存与再来一个` |

**约定（易踩坑）**：本站使用 hash 路由，页面内锚点**不能**再写 `href="#xxx"`（会被当成路由），一律用 `scrollIntoView()`。

补充：`backend/tests/test_api.py` 新增 3 个用例（下载记录持久化标题/封面、`_normalize_thumbnail` 规则、`_backfill_meta` 不覆盖已有值），单元测试 10 passed。
